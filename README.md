# CallNotes — конспекты звонков в Битрикс24

## Клонирование и обученная модель

В репозиторий включена актуальная дообученная модель `models/chechen-ctc-v3/model.pt`
(около 1,3 ГБ), конфигурация и результаты обучения. Веса хранятся через **Git LFS**.
Перед клонированием установите Git LFS, затем выполните:

```bash
git lfs install
git clone https://github.com/hellpains/laram-ai.git
cd laram-ai
git lfs pull
```

Для проверки чеченской модели на Windows запустите `chechen/test-chechen.bat`
(нужен Docker Desktop), добавьте своё аудио в `samples` и выберите `chechen-ctc-v3`.
Остальные базовые модели и токенизатор стенд скачивает при первом запуске.
Дообученная модель используется этим стендом; веб-сервис пока поддерживает
провайдеры Yandex, GigaAM и демо.

Ключи и пароли храните только в локальном `.env` или переменных окружения.
Создайте `.env` из `.env.example` и заполните своими значениями.
`.env`, его резервные копии, приватные ключи, записи звонков, обучающие корпуса
и журналы исключены из Git. Старые версии весов остаются только локально.
Не добавляйте секреты непосредственно в код и не используйте `git add -f` для `.env`.

MVP сервиса: запись звонка → расшифровка (Yandex SpeechKit) → конспект (YandexGPT) → поля сделки, комментарий и задача в Битрикс24.

## Что умеет

- Принимает запись звонка через веб-интерфейс (mp3, wav, ogg, m4a, amr и др.) или по вебхуку от телефонии.
- Распознаёт речь. Стерео-записи (менеджер и клиент в разных каналах) разбираются по каналам, моно — с разметкой говорящих.
- Пишет конспект: суть, чего добились, договорённости, следующий шаг с датой, итог звонка, возражения клиента и замечания для РОПа.
- Находит сделку по телефону клиента (или по ID сделки), заполняет поля, добавляет конспект в ленту и ставит ответственному задачу на следующий шаг.
- Без ключей работает в **демо-режиме** на примере разговора — удобно показать клиенту.

## Быстрый старт (локально)

```bash
pip install -r requirements.txt     # плюс ffmpeg в системе: apt install ffmpeg / brew install ffmpeg
cp .env.example .env                 # пока можно ничего не заполнять — будет демо-режим
python -m app.main                   # откройте http://localhost:8000
```

Тесты: `python -m pytest -q`

## Подключение Yandex Cloud

1. В [консоли Yandex Cloud](https://console.yandex.cloud) создайте каталог и сервисный аккаунт с ролями `ai.speechkit-stt.user` и `ai.languageModels.user`.
2. Создайте API-ключ сервисного аккаунта.
3. Впишите в `.env` значения `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (ID каталога). Перезапустите сервис — плашка «Демо-режим» исчезнет.

Данные обрабатываются в российском облаке, это упрощает соблюдение 152-ФЗ.

## Подключение Битрикс24

1. В Битрикс24: **Разработчикам → Другое → Входящий вебхук**, права `crm`, `task`, `telephony`, `disk`. Скопируйте адрес вида `https://портал.bitrix24.ru/rest/1/xxxx/` в `BITRIX_WEBHOOK_URL`.
2. Создайте поля сделки: `python -m scripts.setup_bitrix`. Появятся «Итог звонка», «Договорённости», «Следующий шаг», «Дата следующего шага».
3. Вынесите эти поля в карточку сделки (настройки карточки в интерфейсе Битрикса).

Как ищется сделка: по номеру находится контакт или компания, берётся последняя открытая сделка. Если сделки нет, но есть лид, конспект пишется комментарием в лид.

## Автоматический приём звонков из Битрикс24

Работает с любой телефонией, подключённой к Битрикс24: встроенной и внешними АТС через приложения из маркетплейса (Mango Office, Zadarma, МТС, Билайн, МегаФон и др.). Выбор АТС на код не влияет.

Как это устроено:
1. Звонок заканчивается → Битрикс24 отправляет событие `ONVOXIMPLANTCALLEND` на `/webhooks/bitrix`.
2. Сервис отбрасывает пропущенные и короткие звонки (`MIN_CALL_SECONDS`).
3. Ждёт, пока АТС прикрепит запись (проверяет каждые `RECORD_POLL_SECONDS`, максимум `RECORD_WAIT_MINUTES`), и скачивает её.
4. Дальше обычный конвейер. Сделка берётся из привязки звонка в Битриксе, задача на следующий шаг ставится менеджеру, который разговаривал.

Настройка:
1. Подключите телефонию к Битрикс24 и **включите запись разговоров** с сохранением записей в Битрикс24 (в настройках АТС или приложения интеграции).
2. Сервис должен быть доступен из интернета по HTTPS, например `https://calls.ваш-домен.ru`.
3. В Битрикс24: **Разработчикам → Другое → Исходящий вебхук**. Адрес обработчика: `https://calls.ваш-домен.ru/webhooks/bitrix`, событие: **«Завершение звонка» (ONVOXIMPLANTCALLEND)**. Сохраните.
4. Скопируйте «Токен приложения» из настроек исходящего вебхука в `BITRIX_APP_TOKEN` и перезапустите сервис.
5. Сделайте тестовый звонок длиннее 20 секунд. Через 1–3 минуты он появится в интерфейсе со статусом «Ждём запись», затем «Готово».

Если звонок завис на «Ждём запись» и упал с ошибкой — значит АТС не передаёт запись в Битрикс24. Проверьте настройки записи в интеграции.

## Вебхук для телефонии напрямую

Запасной вариант, если АТС не подключена к Битрикс24.

```
POST /webhooks/call?secret=<WEBHOOK_SECRET>
{"recording_url": "https://…/record.mp3", "phone": "+79281234567", "call_id": "id-звонка-в-АТС"}
```

`call_id` защищает от повторной обработки одного звонка.

## Развёртывание на сервере

Подробная пошаговая инструкция — в [deploy/DEPLOY.md](deploy/DEPLOY.md). Коротко:

```bash
scp callnotes-mvp.zip root@IP_СЕРВЕРА:/opt/          # с вашего компьютера
ssh root@IP_СЕРВЕРА
cd /opt && apt-get install -y unzip && unzip callnotes-mvp.zip && cd callnotes
sudo bash deploy/install.sh                           # спросит домен, остальное сделает сам
```

Скрипт ставит Docker, генерирует пароль и секреты, запускает сервис за Caddy с автоматическим HTTPS и включает ежедневную резервную копию базы.

## Устройство

```
app/
  main.py          веб-интерфейс, API, вебхук
  pipeline.py      очередь и шаги обработки
  audio.py         ffmpeg: любой формат → OGG Opus
  stt/yandex.py    SpeechKit API v3 (асинхронное распознавание)
  stt/mock.py      демо-расшифровка
  llm/prompt.py    ПРОМПТ конспекта — главное место для настройки качества
  llm/yandexgpt.py YandexGPT
  crm/bitrix.py    поиск сделки, поля, комментарий, задача
  static/index.html интерфейс
scripts/setup_bitrix.py  создание полей сделки
```

Провайдеры распознавания и конспекта сменные (`STT_PROVIDER`, `LLM_PROVIDER`). Чеченский язык добавится как отдельный провайдер в `app/stt/`, остальной конвейер не меняется.

## Ограничения MVP

- Очередь живёт в памяти процесса; незаконченные звонки дообрабатываются после перезапуска. При росте нагрузки — вынести в Redis/RQ.
- Одна компания на один экземпляр сервиса. Мультиклиентность (несколько порталов Битрикс24) — следующий этап.
- Размер записи в SpeechKit передаётся прямо в запросе; для очень длинных записей (час и больше) понадобится Object Storage.
