# Развёртывание CallNotes: пошагово

Время: около 30 минут. Понадобится сервер, домен и доступ к Битрикс24 с правами администратора.

## 1. Сервер

Арендуйте виртуальный сервер **в России** (записи звонков — персональные данные, 152-ФЗ): Yandex Cloud, Selectel, Timeweb Cloud или любой другой.

- Система: **Ubuntu 24.04** (подойдёт и 22.04)
- Минимум: 2 vCPU, 2 ГБ RAM, 30 ГБ диска. Распознавание и конспект делает Yandex Cloud, поэтому мощный сервер не нужен.
- Сохраните IP-адрес и пароль root (или SSH-ключ).

## 2. Домен

Нужен домен или поддомен, например `calls.ваша-компания.ru`. В панели управления доменом создайте **A-запись**: имя `calls`, значение — IP сервера. Запись начинает работать через 5–30 минут.

Проверить можно так: `ping calls.ваша-компания.ru` должен показывать IP сервера.

## 3. Установка

С вашего компьютера загрузите архив на сервер:

```bash
scp callnotes-mvp.zip root@IP_СЕРВЕРА:/opt/
```

Зайдите на сервер и запустите установку:

```bash
ssh root@IP_СЕРВЕРА
cd /opt
apt-get update && apt-get install -y unzip
unzip callnotes-mvp.zip
cd callnotes
sudo bash deploy/install.sh
```

Скрипт спросит домен, затем сам:
- установит Docker;
- создаст файл настроек `.env`, сгенерирует пароль интерфейса и секреты;
- проверит, что домен указывает на сервер;
- запустит сервис и получит HTTPS-сертификат;
- включит ежедневную резервную копию базы.

В конце он покажет адрес интерфейса и пароль. **Сохраните пароль.**

Откройте адрес в браузере. Сервис запустится в демо-режиме — так и должно быть до шага 4.

## 4. Ключи Yandex Cloud

1. В [консоли Yandex Cloud](https://console.yandex.cloud) создайте каталог (или используйте существующий).
2. Создайте сервисный аккаунт с ролями `ai.speechkit-stt.user` и `ai.languageModels.user`.
3. Создайте для него API-ключ.
4. На сервере откройте настройки: `nano /opt/callnotes/.env` и впишите:
   ```
   YANDEX_API_KEY=ключ
   YANDEX_FOLDER_ID=id-каталога
   ```
5. Примените: `cd /opt/callnotes && docker compose up -d`

Плашка «Демо-режим» в интерфейсе исчезнет.

## 5. Битрикс24: запись конспектов

1. **Разработчикам → Другое → Входящий вебхук**. Права: `crm`, `task`, `telephony`, `disk`. Скопируйте адрес вебхука.
2. Впишите его в `.env`: `BITRIX_WEBHOOK_URL=https://портал.bitrix24.ru/rest/1/xxxxxxxx/`
3. Примените и создайте поля сделки:
   ```bash
   docker compose up -d
   docker compose exec app python -m scripts.setup_bitrix
   ```
4. В Битрикс24 откройте любую сделку и вынесите в карточку новые поля: «Итог звонка», «Договорённости», «Следующий шаг», «Дата следующего шага».

Проверка: загрузите запись через интерфейс, указав телефон клиента, у которого есть открытая сделка. Конспект должен появиться в сделке.

## 6. Битрикс24: автоматический приём звонков

1. Подключите телефонию к Битрикс24 и **включите запись разговоров**.
2. **Разработчикам → Другое → Исходящий вебхук**:
   - адрес обработчика: `https://ваш-домен/webhooks/bitrix`
   - событие: **ONVOXIMPLANTCALLEND** (завершение звонка)
3. Скопируйте «Токен приложения» в `.env`: `BITRIX_APP_TOKEN=токен`
4. Примените: `docker compose up -d`
5. Сделайте тестовый звонок длиннее 20 секунд. Через 1–3 минуты он появится в интерфейсе.

## Повседневное обслуживание

| Задача | Команда (в папке `/opt/callnotes`) |
|---|---|
| Состояние сервиса | `docker compose ps` |
| Логи | `docker compose logs --tail=100 app` |
| Перезапуск | `docker compose restart app` |
| Применить изменения `.env` | `docker compose up -d` |
| Резервная копия вручную | `bash deploy/backup.sh` |
| Обновление до новой версии | загрузить новый архив в `/opt`, затем `cd /opt && unzip -o callnotes-mvp.zip && cd callnotes && sudo bash deploy/update.sh` (файл `.env` в архиве нет, настройки сохранятся) |

Резервные копии базы лежат в `/opt/callnotes/backups`, хранятся 14 дней. Скачивайте их время от времени на другой компьютер: копия на том же сервере не спасёт, если сервер сломается.

Восстановление из копии:
```bash
sudo bash deploy/restore.sh backups/calls-ДАТА.db.gz
```

## Если что-то не работает

- **Скрипт пишет, что домен не найден** — A-запись ещё не начала работать. Подождите 15–30 минут и запустите `sudo bash deploy/install.sh` снова.
- **Сайт не открывается по HTTPS** — проверьте, что в панели хостинга открыты порты 80 и 443. Логи Caddy: `docker compose logs caddy`.
- **Звонки из Битрикса не появляются** — проверьте адрес и событие в исходящем вебхуке и токен в `.env`. В логах приложения видны все входящие запросы: `docker compose logs app | grep webhooks`.
- **Звонок упал с ошибкой «Запись не появилась»** — АТС не передаёт записи в Битрикс24. Включите запись и её сохранение в настройках интеграции телефонии.
- **Ошибки Yandex** — текст ошибки виден в карточке звонка. Чаще всего это неверный ключ, ID каталога или не назначены роли сервисному аккаунту.
